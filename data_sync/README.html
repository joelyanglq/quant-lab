data_sync

Standalone market data ETL pipeline. Fetch, store, and monitor financial data from FMP (Financial Modeling Prep).

Quick Start

1. Install Dependencies

pip install pyyaml pandas pyarrow requests rich

2. Configure

Edit data_sync/config.yaml:

  • Set your FMP API key
  • Adjust storage.root if needed (default: ../data relative to config file)
config.yaml contains API keys! Make sure it's in .gitignore.

3. First Sync

# Run from quant-lab/ directory
cd D:\04_Project\quant-lab

# Sync universe first (provides symbol lists for other providers)
python -m data_sync sync --only universe

# Then sync daily bars
python -m data_sync sync --only prices_1d --from 2024-01-01

# Check status
python -m data_sync status

CLI Reference

status — Check sync progress

# Overview of all providers
python -m data_sync status

# Detail for one provider
python -m data_sync status --provider prices_1d

# Per-symbol detail
python -m data_sync status --provider prices_1min --symbols AAPL,MSFT

# Show stale symbols (not updated in N days)
python -m data_sync status --provider financials --stale 30

sync — Run data sync

# Incremental update all providers
python -m data_sync sync

# Only specific providers
python -m data_sync sync --only prices_1d financials

# Historical backfill
python -m data_sync sync --only prices_1d --from 2018-01-01

# Specific symbols
python -m data_sync sync --only financials --symbols AAPL,MSFT,GOOGL

# Limit symbols per run (for resumable partial syncs)
python -m data_sync sync --only prices_1min --limit 50

# Force re-fetch (ignore staleness checks)
python -m data_sync sync --only financials --force

# Use alternate config (e.g., E:/stocks storage)
python -m data_sync --config data_sync/config_estocks.yaml sync

dry-run — Preview without API calls

python -m data_sync dry-run --only prices_1d

Data Sources

ProviderDescriptionAPI EndpointUpdate Strategy
universe Stock list, company profiles, index constituents (SP500, Nasdaq) /stock-list, /profile, /sp500-constituent Full overwrite
prices_1d Daily OHLCV bars, full market /eod-bulk?date=YYYY-MM-DD Incremental by date (1 API call = 1 day, all symbols)
prices_1min 1-minute intraday bars /historical-chart/1min?symbol=X Per-symbol incremental. Concurrent (8 workers). Use --limit for partial runs.
financials Income statement, balance sheet, cash flow /income-statement, /balance-sheet-statement, /cash-flow-statement Per-symbol, 30-day staleness. Concurrent (6 workers).
analysts Analyst consensus estimates /analyst-estimates Per-symbol, 7-day staleness. Append mode (historical snapshots). Concurrent (6 workers).

Provider Execution Order

When running all providers: universe → prices_1d → prices_1min → financials → analysts

universe runs first because it provides the symbol lists used by other providers.

Config Reference

# config.yaml
api_keys:
  fmp: "YOUR_KEY_HERE"

providers:
  prices_1d:
    source: fmp
    bulk: true
  prices_1min:
    source: fmp
    symbols: rus1000           # rus1000 | index | sp500 | nasdaq | all
  financials:
    source: fmp
    symbols: rus1000           # Can also use unions like index+rus1000
    update_interval_days: 30    # Staleness threshold
  analysts:
    source: fmp
    symbols: rus1000
    update_interval_days: 7
  universe:
    source: fmp

storage:
  root: "../data"               # Relative to this file
  prices_1d: "processed/bars_1d"
  prices_1min: "processed/bars_1min"
  financials: "processed/financials"
  analysts: "processed/analysts"
  universe: "processed/universe"

rate_limits:
  fmp: 3000                     # Requests per minute

Symbol Selectors

  • index — SP500 ∪ Nasdaq 100
  • sp500 — SP500 only
  • nasdaq / ndx100 — Nasdaq 100 only
  • all — full active stock list
  • rus1000 — fixed symbol list stored in universe/symbol_layer_rus1000.json
  • Union syntax: index+rus1000 or sp500,rus1000

Important: rus1000 is treated as a fixed list. Normal sync runs do not rebuild it.

python -m data_sync.build_symbol_layers is only a manual re-bootstrap tool, and it does not call FMP or refresh SP500/Nasdaq constituents. It only scans existing monthly parquet files in bars_1min/.

Storage Layout

data/processed/
├── bars_1d/          # {year}_1d.parquet (e.g., 2024_1d.parquet)
├── bars_1min/        # {year}_1m.parquet + _sync_progress.json
├── financials/       # financials.parquet (single file, all symbols)
├── analysts/         # estimates.parquet (append mode, historical snapshots)
├── universe/         # stock_list.parquet, profiles.parquet, index_*.parquet
└── _sync_status.db   # SQLite progress tracking

Status Tracking

Progress is tracked in _sync_status.db (SQLite), updated after each symbol sync. This makes status queries instant without scanning parquet files.

Tip: Use --limit for long-running providers like prices_1min:
python -m data_sync sync --only prices_1min --limit 100
Run this daily — each run picks up where the previous one stopped.

Troubleshooting

ProblemSolution
FileNotFoundError: Config file not found Run from quant-lab/ directory, or use --config flag
No API key configured for source: fmp Edit data_sync/config.yaml and add your FMP key
HTTP 429 rate limit errors Built-in retry handles this. If persistent, reduce rate_limits.fmp in config
Sync interrupted / incomplete Just re-run. Progress is saved per-symbol — it resumes from where it stopped
ModuleNotFoundError: No module named 'rich' pip install rich
Want to use different storage location Use --config data_sync/config_estocks.yaml or edit storage.root in config

Architecture


CLI (cli.py)
  ├── config.yaml → ETLConfig (config.py)
  ├── StatusManager (status.py) → _sync_status.db
  └── Providers (providers/)
        ├── Provider ABC (base.py)
        ├── FMPClient (client/fmp.py) → FMP API
        └── ParquetStorage (storage/parquet.py) → .parquet files
